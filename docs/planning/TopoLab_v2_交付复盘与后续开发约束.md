## 3. B4 的整体复盘

B4.1–B4.51 是 51 个开发切片，包含训练、诊断、软件和文本工作，不是 51 次独立训练。

| 阶段 | 取得的进展 | 仍未解除的阻塞 |
|---|---|---|
| B4.1–8 | 拟合、计时工程修复和开发确认 | 小范围通过后，较大确认出现质量失败 |
| B4.9–14 | 失败诊断、追加优化和终态保留 | 旧反例改善后，新样本仍失败，成本抵消收益 |
| B4.15–29 | 物理目标、局部代理与梯度验证 | 部分正确性进展，成本超限，完整内存未证明 |
| B4.30–31 | 反射修复与审查 | 固定 P/17 的失败未修复 |
| B4.32–51 | 11 个文本切片、9 个小型公共软件切片 | 没有实际 FEM/拟合验证或新的学习修复结论 |

主要问题如下。

1. **可靠性修复没有稳定迁移。** B4.5/B4.7 的局部通过随后被更大确认中的失败否定。
   修复暴露反例不等于获得跨样本可靠性；不能用更好的 MSE 或局部速度替代终态质量。
   见 [B4.8](../validation/b4_8_rollback_confirmation.md)和
   [B4.30](../validation/b4_30_paid_continuation.md)。
2. **资源可行性没有及时淘汰路线。** B4.15 的训练预测约 60339 秒，对应上限 7200 秒。
   当前口径的已知已付小计 `12721.16417100014444982 > 7200`，即使未来零新增也不能通过
   原全计费要求。该小计不是全项目账本；预测成本也不是已经发生的支出。
   见 [B4.15](../validation/b4_15_offline_compliance_adjoint.md)和
   [B4.34](../validation/b4_34_admissibility_full_cost_preregistration.md)。
3. **可避免的工程错误消耗正式机会。** B4.42 状态字符串检查错误、B4.43 启动导入失败，
   以及 B4.51 lint 失败后冻结、修改冻结源码并继续调用，均不是模型失败的证据。
   尤其 B4.51 的冻结和停止处理是执行失误，后续 TEXT 结果不能恢复合规。
   见 [B4.42](../validation/b4_42_public_enclosure_limitations_real_assembly.md)、
   [B4.43](../validation/b4_43_public_assembled_residual_enclosure.md)和
   [B4.51](../validation/b4_51_real_certification_executable_full_resource_preregistration.md)。
4. **认证工具研发逐渐偏离交付关键路径。** 小型公共系统的精确算术和证明有技术价值，
   但尚未证明能够以可接受成本改善真实学习方法。原平台交付清单并不普遍要求逐操作认证；
   若选择的数学路线确实依赖它，仍须证明该依赖的必要性与可行性。
5. **跨切片的项目决策不足。** 各片有限，整个研究计划仍可因不断产生后继而无限延长。
   此前过度关注单片合规收尾，没有持续检验下一片是否缩短到最终验收的距离。
   B4.32–34 已确认的预算阻塞本应更早触发整体路线决策。

结论：近期 B4 的工作重心偏离交付关键路径，执行与项目管理方法需要纠正。
保留失败、独立审计、封存和完整计费仍然必要；改进来自路线选择和执行质量，
不来自放宽标准、替换主模型、删除历史或重置配额。

## 4. 后续必须执行的工作规则

1. **先恢复实际证据。** 每片开始、上下文压缩恢复、提交或推送前，重新读取
   AGENTS、本文、当前状态和适用合同，核对最新 main、CI、PR、实际执行记录。
   当前入口负责排期；冻结历史中的旧后继文字不构成当前授权。
2. **每片对应一个交付阻塞或淘汰决定。** 开始前写清基线、目标能力、验收证据、
   依赖、范围、资源和失败后的决定。纯文档或守卫工作须说明它会解锁什么、
   在哪一个有限步骤中接回真实能力验证；不另建无终点的文本/玩具/限制循环。
3. **先判断可达性。** 历史已付成本、乐观新增成本和同时内存约束必须先核对。
   已证不可达则停止该口径的实现投入并提出具体所有者决策。
   新合同提案不是新预算授权，不能剔除旧成本或更改旧 Gate。
4. **区分失败类别。** 分别报告科学质量/速度失败、资源不可行、工程/流程失败和 UNKNOWN。
   技术 CI、文本一致性、小型公共软件通过都不能代替科学通过。
   缺失运行时和原因继续 UNKNOWN，不用新运行补造旧证据。
5. **正式执行前完成软件集成预检。** 使用获准公开测试验证实际解释器、argv、cwd、
   导入及依赖来源、角色路径、原子记录和失败控制；完成要求的检查后再冻结。
   生产仍须干净、锁定、已合并且适用 CI 全通过的源码。
   冻结后变更、预检失败或停止条件触发即拒绝启动，不自动修复后继续。
   普通开发测试不等于正式调用；已消耗正式机会不能恢复。
6. **限制连续的低效推进。** 最多连续两个能力切片后复核关键阻塞变化；
   若没有关闭阻塞或淘汰有实质区别的路线，停止默认追加，进行一次明确的路线决策。
   两片窗口是治理复核上限，不是新增实验次数、预算或自动连续执行授权。
7. **阶段交付持续存在。** 平台改进和 ML 研究分别报告成果。平台工作单独授权、
   单独验收，不能改变冻结数值比较分母；完整 v2 正向交付条件继续保留。
8. **保持记录精简、可复现。** 当前状态只写最新结论、阻塞和下一项工作；
   历史和冻结证据保留原路径与内容。用链接定位细节，避免在多个入口复制完整历史。
   汇总应给出源码版本、复现入口和必要外部哈希；数据、模型、日志和数据库仍在 Git 外。

每次收尾优先报告：关闭/淘汰了什么、固定主模型质量和失败变化、端到端成本、
同时内存证据、剩余阻塞及下一步。检查数量是辅助信息。
所有既有必需检查、发布守卫、PR 最新提交 CI、main CI 和审查要求继续执行。

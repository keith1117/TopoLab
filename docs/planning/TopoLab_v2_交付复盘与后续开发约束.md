## 1. 所有者确认的目标

- `v1.0.0` 是已经完成、可以展示的阶段交付成果；后续平台改进继续保留其价值。
- 完整 v2 仍以旗舰水平为目标，继续要求证据支持的同质量、端到端学习加速。
  平台成熟度和负面实验结论不能代替该正向科研条件。
- 后续工作须持续交付可验收能力，或通过有限证据淘汰不可行路线。
  不能用不断增加切片、文档、测试或审计谓词代替交付推进。
- 工程流程的可靠性可以改进；任何模型的正向科研结果都不能预先保证。

本文件控制后续工作方式；[英文 v2 路线图](TopoLab_v2_development_roadmap.md)
继续控制科学 Gate 顺序，现有冻结合同控制各自实验的访问、容差、预算和停止条件。
本文只取代当前入口中“默认继续 B4.52”的排期，不追溯改写任何历史后继决定。

## 3. B4 的整体复盘

B4.1–B4.51 是 51 个开发切片，包含训练、诊断、软件和文本工作，不是 51 次独立训练。

| 阶段 | 取得的进展 | 仍未解除的阻塞 |
|---|---|---|
| B4.1–8 | 拟合、计时工程修复和开发确认 | 小范围通过后，较大确认出现质量失败 |
| B4.9–14 | 失败诊断、追加优化和终态保留 | 旧反例改善后，新样本仍失败，成本抵消收益 |
| B4.15–29 | 物理目标、局部代理与梯度验证 | 部分正确性进展，成本超限，完整内存未证明 |
| B4.30–31 | 反射修复与审查 | 固定 P/17 的失败未修复 |
| B4.32–51 | 11 个文本切片、9 个小型公共软件切片 | 没有实际 FEM/拟合验证或新的学习修复结论 |

主要问题如下。

1. **可靠性修复没有稳定迁移。** B4.5/B4.7 的局部通过随后被更大确认中的失败否定。
   修复暴露反例不等于获得跨样本可靠性；不能用更好的 MSE 或局部速度替代终态质量。
   见 [B4.8](../validation/b4_8_rollback_confirmation.md)和
   [B4.30](../validation/b4_30_paid_continuation.md)。
2. **资源可行性没有及时淘汰路线。** B4.15 的训练预测约 60339 秒，对应上限 7200 秒。
   当前口径的已知已付小计 `12721.16417100014444982 > 7200`，即使未来零新增也不能通过
   原全计费要求。该小计不是全项目账本；预测成本也不是已经发生的支出。
   见 [B4.15](../validation/b4_15_offline_compliance_adjoint.md)和
   [B4.34](../validation/b4_34_admissibility_full_cost_preregistration.md)。
3. **可避免的工程错误消耗正式机会。** B4.42 状态字符串检查错误、B4.43 启动导入失败，
   以及 B4.51 lint 失败后冻结、修改冻结源码并继续调用，均不是模型失败的证据。
   尤其 B4.51 的冻结和停止处理是执行失误，后续 TEXT 结果不能恢复合规。
   见 [B4.42](../validation/b4_42_public_enclosure_limitations_real_assembly.md)、
   [B4.43](../validation/b4_43_public_assembled_residual_enclosure.md)和
   [B4.51](../validation/b4_51_real_certification_executable_full_resource_preregistration.md)。
4. **认证工具研发逐渐偏离交付关键路径。** 小型公共系统的精确算术和证明有技术价值，
   但尚未证明能够以可接受成本改善真实学习方法。原平台交付清单并不普遍要求逐操作认证；
   若选择的数学路线确实依赖它，仍须证明该依赖的必要性与可行性。
5. **跨切片的项目决策不足。** 各片有限，整个研究计划仍可因不断产生后继而无限延长。
   此前过度关注单片合规收尾，没有持续检验下一片是否缩短到最终验收的距离。
   B4.32–34 已确认的预算阻塞本应更早触发整体路线决策。

结论：近期 B4 的工作重心偏离交付关键路径，执行与项目管理方法需要纠正。
保留失败、独立审计、封存和完整计费仍然必要；改进来自路线选择和执行质量，
不来自放宽标准、替换主模型、删除历史或重置配额。

## 4. 已生效的开发方法

所有者于2026-10-16批准。这些是流程规则，不改变验收、预算、访问或资源准入标准；
适用冻结合同的现有义务仍须满足。

1. **恢复实际证据。** 每片开始、恢复上下文及提交/推送前，实际读取AGENTS、本文、
   当前状态和适用合同，核对最新main/CI/PR及实际记录。当前入口控制排期，冻结历史的旧后继
   不构成当前授权；未解决的实质矛盾阻止依赖操作。
2. **先定验收规格和资源保证方式，再选算法。** 每个要求写明保障哪项最终交付、依据与适用合同、
   所需证据、选定环境/角色，以及证据是否实际可取得。实现前写清有限能力、基线、范围、依赖、
   成本/内存上限、验收及退出。特定算法的数学证书不自动成为所有学习路线的共同前提；
   所选适用合同要求该证书、完整资源证明或其他义务时仍须满足，不能据此豁免。
   必需证据缺失即停止准入，不等于证明所有路线均不可行。
3. **先查可达性和全计费。** 包括历史已付、乐观新增、完整同时生命周期及独立审查。
   已知已付12721.16417100014444982>7200永久不满足原全计费条件，继续实现不能修复该口径。
   必要时提出有限所有者决定；不能排除历史、重置账本、转移未用额度或把提案当授权。
   未知成本/内存仍为UNKNOWN，不是零或试跑许可。
4. **正式冻结前调试公开软件。** 获准公开测试须覆盖实际启动命令/解释器、argv、cwd、
   依赖及导入来源、权限、公开输入身份、角色路径、原子记录及失败前缀，不授予旧输入访问。
   规定检查在冻结前完成。生产另须干净、锁定、已合并且适用CI全通过的源码、实际输入/角色登记
   及独立实际启动预检。冻结后变更或触发STOP即拒绝继续正式启动，不修补后续跑，不恢复旧配额。
5. **另行获准恢复科研后，一次只验证一个有限假设。** 在结果前说明机制、预期质量/成本效果、
   对照、完整计费及明确验收/退出。暴露样本用于开发回归，新独立样本用于确认；
   修复、确认、完整B4和最终B5各有[独立目的与顺序](TopoLab_v2_开发路线图.md#6-推荐执行顺序)。
   每个实际阶段都另须授权、预算、访问、预注册、资源准入、冻结和独立审查，前片不授权后片。
6. **衡量阻塞变化。** 记录固定P/17失败数、最坏质量差距、完整计费速度、资源准入、已用与剩余
   预算，并标明样本/方法/源码身份及前后变化。路线图保留已公布基线；未测量或未获准测量的字段
   保持UNKNOWN，不为填表启动实验。测试/文档数量仅为辅助。最多两个能力切片没有实质阻塞改善
   或淘汰实质不同路线时，必须明确复核路线，不默认追加。两片窗口不授权第二片、调用或预算。
7. **分别报告结论。** 科学质量/速度失败、已证明的资源不可行、工程/流程失败和UNKNOWN分开。
   技术CI、文本一致或公开测试不通过科研Gate、不补造旧证据或完整训练内存证明。
   不保证正向模型结果或P/17修复日期。
8. **平台能力单独验收。** A2.3检查点/恢复可在另行指令和冻结合同后成为平台下一候选：
   恢复与不中断运行的密度/柔度/体积在冻结容差内一致；损坏或身份不匹配的检查点被拒绝；
   崩溃期间发布保持原子性；保留fenced ownership并拒绝失效所有者写入。
   它不计作P/17修复或科研通过，本次未实施、未立项。A2.4/A4依赖不变。
9. **记录精简可复现，权限类别明确。** 当前状态写当前阻塞和唯一下一项；历史/冻结证据保留
   原路径与字节。链接源码版本、复现入口及必要外部哈希，数据/模型/日志/数据库留在Git外。
   当前入口均区分已生效规则、待决定建议及历史结论；所有既有检查、发布守卫、精确PR提交CI
   及合并后main CI继续执行。
